READ THIS BEFORE THE TABLE Both prototypes are design artifacts: single HTML files with in-file state. There is no database, no queue, no AI provider call, no auth, no scheduler and no notification transport anywhere in this project. Every number, every concept, every question and every run is a literal in the file. So the honest answer to "is the engine implemented" is no — not one workflow of it, and that is true of the benchmark UI as much as the learner UI. What I can build here is the product's interaction design with realistic client-side state — including the parts currently missing (knowledge gaps, R/O/G judgement, concept priority, demonstration library, question studio, revision dashboard). Real ingestion, chunked resumable processing, model calls, validation, persistence and scheduled notifications need a server; I can specify them precisely and design against them, but I can't run them from this file. I've marked that boundary everywhere below rather than blur it.
